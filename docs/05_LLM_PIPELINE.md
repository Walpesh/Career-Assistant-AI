# LLM Pipeline — промпты, режимы анализа и генерации

## 1. Общие принципы работы с LLM

- Основной движок: **Ollama** (локальный режим, приоритетный)
- Поддержка внешних LLM API (OpenAI-compatible) через единый интерфейс
- Все запросы к LLM выполняются **строго последовательно** (одна глобальная или per-user очередь)
- Каждый вызов LLM логируется (промпт + ответ + время выполнения)
- Для снижения расхода контекста используется обязательное сокращение резюме (`compact_resume`)

### Входные данные для всех LLM-операций
- `compact_resume` — сокращённая версия резюме пользователя
- Очищенное описание вакансии (`description_raw` + ключевые поля)
- Режим работы
- Порог матчинга (из профиля или переопределённый)

---

## 2. Режимы обработки вакансий

| Режим                  | Код                     | Что делает                                      | Когда использовать |
|------------------------|-------------------------|-------------------------------------------------|--------------------|
| Только Анализ          | `analyze`               | Анализ + расчёт match_score                     | Когда нужно понять соответствие |
| Только Письмо          | `letter`                | Генерация сопроводительного письма              | Когда анализ уже есть |
| Анализ + Письмо        | `analyze_and_letter`    | Полный цикл                                     | Ручной запуск «здесь и сейчас» |
| AUTO                   | `auto`                  | Анализ → проверка порога → письмо (если прошёл) | Массовая обработка и автопоиск |

---

## 3. Этап 0. Конвертация резюме (обязательный метод)

**Назначение:** создать компактную версию резюме, чтобы не раздувать контекст модели.

**Промпт (system + user):**

```text
Ты — опытный HR-ассистент и карьерный консультант.
Твоя задача — максимально сжать резюме кандидата, сохранив только ключевую информацию, важную для оценки соответствия вакансиям.

Правила:
- Убери воду, общие фразы и повторы
- Оставь: опыт работы (годы + ключевые роли), основные навыки, образование, достижения с цифрами, стек технологий
- Сохрани профессиональный тон
- Объём результата — не более 1800–2200 символов
- Язык ответа — русский

Резюме кандидата:
{resume_text}
```

Результат сохраняется в `user_profiles.compact_resume`.

---

## 4. Этап 1. Анализ вакансии + Матчинг

**Используется в режимах:** `analyze`, `analyze_and_letter`, `auto`

**Промпт:**

```text
Ты — строгий и объективный HR-эксперт с 15-летним опытом подбора IT и digital-специалистов.

Проанализируй, насколько кандидат соответствует вакансии.

Данные кандидата (compact resume):
{compact_resume}

Данные вакансии:
Название: {title}
Компания: {company_name}
Опыт: {experience}
Формат работы: {work_format}
Занятость: {employment_form}
Зарплата: {salary}
Описание:
{description_raw}

Задача:
1. Оцени соответствие по шкале от 0 до 100.
2. Выдели сильные стороны кандидата именно под эту вакансию.
3. Выдели слабые стороны и риски.
4. Дай краткий итоговый вывод (2–3 предложения).

Ответ строго в JSON-формате:
{
  "match_score": 0-100,
  "strengths": ["...", "..."],
  "weaknesses": ["...", "..."],
  "summary": "..."
}
```

После получения ответа:
- `match_score` сохраняется в `vacancies.match_score` и в таблицу `analyses`
- В режиме `auto` происходит проверка:  
  `if match_score >= threshold → запускаем генерацию письма`

---

## 5. Этап 2. Генерация сопроводительного письма

**Используется в режимах:** `letter`, `analyze_and_letter`, `auto` (при прохождении порога)

**Промпт:**

```text
Ты — профессиональный карьерный консультант, который пишет сильные, живые и убедительные сопроводительные письма.

Напиши сопроводительное письмо от кандидата на вакансию.

Данные кандидата:
{compact_resume}

Вакансия:
Название: {title}
Компания: {company_name}
Описание:
{description_raw}

Требования к письму:
- Объём: 1200–1800 символов
- Структура: приветствие → почему я подхожу (с опорой на опыт) → что могу дать компании → призыв к действию
- Тон: уверенный, профессиональный, без канцелярита и воды
- Не используй шаблонные фразы («Буду рад возможности», «Рассмотрите мою кандидатуру» и т.д.)
- Письмо должно быть готово к копированию и отправке
- Язык: русский

Верни только текст письма, без пояснений и заголовков.
```

Результат сохраняется в таблицу `cover_letters`.

---

## 6. Логика режима AUTO

```text
1. Запускается анализ вакансии
2. Получаем match_score
3. Сравниваем с порогом:
   - Порог берётся из запроса (если передан)
   - Иначе — из профиля пользователя (user_profiles.match_threshold)
4. Если match_score >= threshold:
      → автоматически запускается генерация письма
      → статус вакансии становится letter_ready
5. Если match_score < threshold:
      → письмо не генерируется
      → статус вакансии становится analyzed
```

## 7. Обработка ошибок LLM

| Ситуация                        | Действие                                      |
|--------------------------------|-----------------------------------------------|
| Модель вернула невалидный JSON | Повторный запрос (до 2 раз) + жёсткий промпт «верни только JSON» |
| Таймаут / Ollama недоступна    | Задача переводится в failed + уведомление     |
| Слишком длинный контекст       | Используется только compact_resume + усечённое описание вакансии |
| Галлюцинации в письме          | Пост-обработка: проверка на наличие ключевых запрещённых фраз |

---

## 8. Рекомендуемые параметры Ollama

```json
{
  "temperature": 0.35,          // для анализа
  "temperature": 0.55,          // для генерации писем
  "top_p": 0.9,
  "num_ctx": 8192,
  "repeat_penalty": 1.1
}
```

Для анализа рекомендуется более детерминированная температура, для писем — чуть выше, чтобы текст был живым.

---

## 9. Версионирование писем

При повторной генерации письма для той же вакансии:
- Создаётся новая запись в `cover_letters` с `version = previous + 1`
- Или обновляется существующая запись (на выбор реализации)
- В интерфейсе пользователь видит актуальную версию + возможность посмотреть предыдущие
```
